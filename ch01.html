Chapter 1 — Python Foundations

This is your first notebook. We learn the building blocks of Python using tiny, real geospatial examples — coordinates and shapes for two places we will return to throughout: the Malcolm Knapp Research Forest (MKRF) in British Columbia and the mangrove coast of NW Madagascar.

No prior Python experience is assumed. Run each code cell, read the output, and try the Try it yourself prompts.

  3. Build and index lists, tuples, and dictionaries.
  4. Construct a file path with pathlib.
  5. Import a package and use it.
  6. Make a simple Shapely Point, LineString, and Polygon from coordinates.

1. Variables: describing a field site¶

A variable is a name that stores a value. Let's describe the MKRF research forest. Notice the different types: text (str), whole numbers (int), decimals (float), and true/false (bool).

In [2]:
# A variable = name on the left, value on the right
site_name   = "Malcolm Knapp Research Forest"   # str  (text, in quotes)
latitude    = 49.27                              # float (decimal degrees North)
longitude   = -122.57                            # float (decimal degrees; West is negative)
elevation_m = 150                                # int  (whole number, metres)
is_protected = True                              # bool (True or False)

print(site_name + ":", latitude, "latitude,", longitude, "longitude")

Malcolm Knapp Research Forest: 49.27 latitude, -122.57 longitude

2. Operators: doing things with values¶

Arithmetic (+ - * /), comparison (> < ==), and logical (and or not) operators let us compute and ask questions about our data.

In [4]:
# Arithmetic
elevation_ft = elevation_m * 3.281
print("Elevation in feet:", round(elevation_ft, 1))

# Comparison -> gives a boolean
in_northern_hemisphere = latitude > 0
print("Northern hemisphere?", in_northern_hemisphere)

# Logical: combine conditions
print("Protected AND northern?", is_protected and in_northern_hemisphere)

Northern hemisphere? True
Protected AND northern? True

3. Data structures: grouping many values¶

Real geospatial work involves collections of values. Three you will use constantly:

Structure Looks like Use it for Changeable?
list [a, b, c] an ordered, editable collection yes
tuple (x, y) a fixed pair/record (e.g. a coordinate) no
dict {"key": value} labelled attributes of one thing yes
In [5]:
# A tuple: one coordinate pair (longitude, latitude) -- fixed
mkrf_point = (-122.57, 49.27)

# A list: several plot coordinates in MKRF -- ordered and editable
plot_coords = [
    (-122.573, 49.271),
    (-122.569, 49.268),
    (-122.566, 49.274),
]

# A dictionary: labelled attributes of one site
site = {
    "name": "MKRF",
    "lon": -122.57,
    "lat": 49.27,
    "elevation_m": 150,
    "protected": True,
}

print("Number of plots:", len(plot_coords))
print("Site name from dict:", site["name"])

Number of plots: 3
Site name from dict: MKRF

Indexing pulls items out. Python counts from 0:

print("First plot:", plot_coords[0])     # index 0 = first
print("Last plot: ", plot_coords[-1])     # -1 = last

# Lists are editable: add a new plot
plot_coords.append((-122.571, 49.269))
print("Now there are", len(plot_coords), "plots")

First plot: (-122.573, 49.271)
Last plot:  (-122.566, 49.274)

✅ Quick check — indexing¶

For plots = [(-122.57, 49.27), (-122.55, 49.29)], what does plots[1][0] give?

▶ Show answer -122.55 — the second tuple (index 1), then its first value (index 0), the longitude. Remember indexing starts at 0.

🌲 Why code this? A forest inventory is a list of plot dictionaries; a species-code table is a dictionary. Lists and dicts hold many records at once — no separate variable per tree — which is exactly the idea behind Pandas (Chapter 3).

4. File paths with pathlib¶

Your data lives in files. pathlib builds paths that work on Windows, Mac, and Linux. Use the / operator to join folders — cleaner and safer than typing "data\\sites.csv" by hand.

In [7]:
from pathlib import Path

data_dir = Path("data")            # a folder (relative path)
sites_file = data_dir / "sites.csv"  # join folder + filename

print("Full path:", sites_file)
print("File name:", sites_file.name)
print("Extension:", sites_file.suffix)

Full path: data\sites.csv
File name: sites.csv
Extension: .csv

We will treat relative paths (like data/sites.csv) as the reproducible default and revisit why in Chapter 5 (files & data quality).

🌲 Why code this? Environmental data lives in hundreds of files (shapefiles, rasters, CSVs). Building paths in code means the same analysis re-runs on a new folder of survey data, on any computer — no manual re-typing, no broken links.

5. Importing packages¶

Python's power comes from packages. You import a package, then use its tools with a dot: package.tool(). Here is the built-in math package.

In [8]:
import math

# straight-line distance between two of our plots (in DEGREES for now)
d = math.dist(plot_coords[0], plot_coords[1])
print("Planar distance:", round(d, 5), "degrees")

Planar distance: 0.005 degrees

Notice the distance is in degrees, which is not a real-world length. Turning coordinates into metres needs a coordinate reference system — the topic of Chapter 5. For now, just notice the problem exists.

🌲 Why code this? Nobody re-writes geospatial math from scratch. Importing packages (NumPy, GeoPandas, Rasterio) lets you build on tested tools — the difference between an afternoon and a month on a mangrove-loss analysis.

6. Your first geometries: Shapely¶

A coordinate pair is just numbers. Shapely turns coordinates into geometry objects — Point, LineString, Polygon — the same objects that GeoPandas (Chapter 4) uses for whole datasets. This is a tiny first taste.

In [9]:
from shapely.geometry import Point, LineString, Polygon

# A Point: one location (lon, lat)
mkrf = Point(-122.57, 49.27)

# A LineString: an ordered path (e.g. a short trail) through several points
trail = LineString([(-122.573, 49.271), (-122.569, 49.268), (-122.566, 49.274)])

# A Polygon: a closed area (first and last point join automatically)
stand = Polygon([(-122.575, 49.270), (-122.565, 49.270),
                 (-122.565, 49.276), (-122.575, 49.276)])

print("Point:      ", mkrf)
print("Trail length:", round(trail.length, 5), "degrees")
print("Stand area: ", round(stand.area, 6), "square degrees")

Point:       POINT (-122.57 49.27)
Trail length: 0.01171 degrees
Stand area:  6e-05 square degrees

✅ Quick check — geometry order¶

To place a point at latitude 49.3, longitude −122.6, do you write Point(49.3, -122.6) or Point(-122.6, 49.3)?

▶ Show answer Point(-122.6, 49.3) — Shapely takes (lon, lat). Writing (lat, lon) puts the point in the wrong place (a classic bug).

Bonus 1 — Formatting output with f-strings¶

Why code this? A result only matters if you can communicate it. An f-string drops variables into a string, so you can build clean report lines, map labels, and messages from your data — something you'll do in every chapter of this book.

In [12]:
species = "Douglas-fir"
dbh_cm  = 47.5
plot_id = 12

# an f-string starts with f"..." — put variables inside { }
print(f"Plot {plot_id}: {species}, DBH {dbh_cm} cm")
print(f"That is about {dbh_cm / 2.54:.1f} inches.")   # :.1f = round to 1 decimal

Plot 12: Douglas-fir, DBH 47.5 cm
That is about 18.7 inches.

🌲 Instead of printing bare numbers, foresters format results into readable summaries — e.g. a per-plot line in a stand report, or a label on a map.

Bonus 2 — A forest inventory as a list of dictionaries¶

Why code this? Real datasets are collections of records. Modelling a forest inventory as a list of dictionaries — one dict per plot — is the exact mental model behind every table you'll meet in Pandas (Chapter 3) and GeoPandas (Chapter 4). Learn it here in miniature and those chapters feel familiar.

In [13]:
# each tree/plot is a dictionary; the inventory is a list of them
inventory = [
    {"plot": 1, "species": "Douglas-fir",      "dbh_cm": 47.5},
    {"plot": 2, "species": "western redcedar", "dbh_cm": 61.0},
    {"plot": 3, "species": "Douglas-fir",      "dbh_cm": 28.0},
]

# loop over the records
for tree in inventory:
    print(tree["plot"], "-", tree["species"], "-", tree["dbh_cm"], "cm")

# a quick summary: average DBH across the inventory
dbhs = [tree["dbh_cm"] for tree in inventory]
print("Average DBH:", round(sum(dbhs) / len(dbhs), 1), "cm")

1 - Douglas-fir - 47.5 cm
2 - western redcedar - 61.0 cm
3 - Douglas-fir - 28.0 cm
Average DBH: 45.5 cm

🌲 This is a forest inventory table, built from plain Python. In Chapter 3 Pandas will do the looping and summarising for you — but it's the same idea.

1. Comprehensions — a loop on one line¶

A list comprehension builds a new list from an old one. It reads like English: value for each item.

In [ ]:
heights_m = [30, 42, 51, 28, 47]
heights_ft = [round(h * 3.28084, 1) for h in heights_m]   # metres -> feet
print(heights_ft)

tall = [h for h in heights_m if h > 40]                   # keep only the tall trees
print("tall (>40 m):", tall)

A dict comprehension does the same for dictionaries — here, counting species codes.

In [ ]:
species = ["Df", "Cw", "Hw", "Df", "Cw"]
counts = {s: species.count(s) for s in set(species)}
print(counts)

codes = {"Df": "Douglas-fir", "Cw": "western redcedar", "Hw": "western hemlock"}
print([codes[s] for s in species])

✅ Quick check — comprehensions¶

What does [x*x for x in [1, 2, 3, 4] if x % 2 == 0] produce?

✅ Show answer [4, 16] — it keeps only the even numbers (2 and 4), then squares each.

2. f-string formatting — a tidy report¶

Inside an f-string, : starts a format spec: < left-aligns, > right-aligns, .1f fixes one decimal.

In [ ]:
plots = [("A1", 47.5), ("A2", 61.0), ("B1", 28.0)]
for name, dbh in plots:
    print(f"{name:<4} DBH {dbh:>6.1f} cm")

3. Functions with a default and a docstring¶

A default argument lets a caller skip it. The """docstring""" documents what the function does.

In [ ]:
def dbh_class(dbh_cm, threshold=50):
    """Return 'large' if dbh_cm is above threshold, else 'small'."""
    return "large" if dbh_cm > threshold else "small"

print(dbh_class(61), dbh_class(28), dbh_class(45, threshold=40))
print(dbh_class.__doc__)

4. Safe input with try / except¶

Real field data has typos. try/except lets your code keep going instead of crashing.

In [ ]:
def safe_lat(value):
    """Return a valid latitude float, or None if the value is bad."""
    try:
        v = float(value)
        return v if -90 <= v <= 90 else None
    except ValueError:
        return None

print(safe_lat("49.27"), safe_lat("oops"), safe_lat(120))

🌲 Why code this? Comprehensions and small functions are how you turn a one-off script into a reusable tool — the same dbh_class runs on 5 trees or 50,000, and safe_lat quietly cleans a messy inventory file instead of stopping at the first typo.

🌟 Challenge¶

Write a function mean_dbh(records, species) that takes a list of (species, dbh) tuples and returns the average DBH for one species (or None if that species is absent).

🌟 Show one solution 
def mean_dbh(records, species):
    vals = [d for s, d in records if s == species]
    return round(sum(vals) / len(vals), 1) if vals else None

data = [("Df", 47.5), ("Cw", 61.0), ("Df", 28.0)]
print(mean_dbh(data, "Df"))   # 37.8
print(mean_dbh(data, "Hw"))   # None
