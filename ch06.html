The end-to-end pipeline (Chapters 1–5 in one flow)¶

Table → clean (Pandas) → points (GeoPandas) → reproject & QA (CRS) → summarize → export. Read each step and notice which chapter taught it.

import pandas as pd
import geopandas as gpd
from pathlib import Path

# 1) TABLE (Chapter 3): load and clean
# In the course: df = pd.read_csv("data/fires_clean.csv"). Small MKRF sample here:
df = pd.DataFrame({
    "site":   ["MKRF-N", "MKRF-N", "MKRF-S", "MKRF-S"],
    "lon":    [-122.57, -122.55, -122.52, -122.50],
    "lat":    [49.31, 49.32, 49.27, 49.28],
    "area_ha":[12.5, 3.0, 40.0, 22.0],
})
df = df.dropna(subset=["lat", "lon"])            # need coordinates to map

# 2) POINTS (Chapter 4): build a GeoDataFrame
gdf = gpd.GeoDataFrame(
    df, geometry=gpd.points_from_xy(df["lon"], df["lat"]), crs="EPSG:4326"
)

# 3) CRS + QA (Chapter 5): reproject, then check quality
gdf_m = gdf.to_crs("EPSG:3005")
print("invalid geometries:", (~gdf_m.geometry.is_valid).sum())
print("duplicate rows:", gdf_m.duplicated().sum())

# 4) SUMMARIZE (Chapter 3): area burned per site
print(gdf_m.groupby("site")["area_ha"].sum())

# 5) EXPORT (Chapters 4–5): reproducible output
Path("outputs").mkdir(exist_ok=True)
gdf_m.to_file("outputs/fires_bcalbers.gpkg", driver="GPKG")
print("Wrote outputs/fires_bcalbers.gpkg")

Debugging clinic — the usual suspects¶

When something breaks, check these first (each maps to a chapter):

  1. Path wrong / absolute → Chapter 5 (use relative paths).
  2. CRS missing or mismatched → Chapters 4–5 (gdf.crs, .to_crs).
  3. Merge key wrong → Chapter 3 (check the on= column and row counts).
  4. Missing values → Chapter 3 (isna().sum(), decide fill vs drop).
  5. (lon, lat) reversed → Chapters 1 & 4 (x = longitude first).

Bonus — Wrap the whole pipeline in one reusable function¶

Why code this? Once a workflow works, package it. Next season's survey becomes a one-line call instead of a re-run of twenty cells — the difference between a script and a tool.

In [ ]:
import pandas as pd, geopandas as gpd
from pathlib import Path

def plots_to_gpkg(df, out_path, to_crs="EPSG:3005"):
    """Table with lon/lat -> cleaned, reprojected GeoPackage. Returns the GeoDataFrame."""
    df = df.dropna(subset=["lon", "lat"])
    gdf = gpd.GeoDataFrame(df, geometry=gpd.points_from_xy(df["lon"], df["lat"]),
                           crs="EPSG:4326").drop_duplicates()
    gdf = gdf.to_crs(to_crs)
    Path(out_path).parent.mkdir(exist_ok=True, parents=True)
    gdf.to_file(out_path, driver="GPKG")
    return gdf

demo = pd.DataFrame({"site": ["A", "B"], "lon": [-122.57, -122.55], "lat": [49.27, 49.29]})
result = plots_to_gpkg(demo, "outputs/demo_plots.gpkg")
print("rows:", len(result), "| CRS:", result.crs)

🌲 Reuse this on any new plot table — the same five steps, one call.

import pandas as pd, geopandas as gpd

plots = pd.DataFrame({
    "plot": ["A", "B", "C", "D"],
    "lon":  [-122.57, -122.55, 48.55, 48.58],
    "lat":  [49.27, 49.29, -13.35, -13.33],
    "dbh_cm":[47, 61, 28, 40],
})
print(plots)

2. Make points, then region polygons¶

points_from_xy builds geometry straight from lon/lat columns.

In [ ]:
gdf = gpd.GeoDataFrame(plots, geometry=gpd.points_from_xy(plots.lon, plots.lat),
                       crs="EPSG:4326")
regions = gpd.GeoDataFrame({"region": ["MKRF", "Ambaro"]},
    geometry=[box(-123, 49, -122, 50), box(48, -14, 49, -13)], crs="EPSG:4326")
print(gdf.geometry.geom_type.tolist())

3. Spatial join, then summarise by region¶

This is the payoff — a tabular summary that came from where the points are.

In [ ]:
joined = gpd.sjoin(gdf, regions, predicate="within", how="left")
summary = joined.groupby("region")["dbh_cm"].agg(["count", "mean"]).round(1)
print(summary)

✅ Quick check — workflow¶

Why must both gdf and regions share the same CRS before sjoin?

✅ Show answer A spatial join compares coordinates directly — if the two layers use different CRSs, the same real-world spot has different numbers and the join is wrong. Match with .to_crs() first.

🌲 Why code this? This tabular → spatial → summary pattern is Lab 1, and most real projects: read messy field data, put it on the map, and report a number per management unit. Master the shape here and every later analysis is a variation on it.

🌟 Challenge¶
