Chapter 8 — ArcPy: Automation

Last week we ran single tools. This week is ArcPy's real payoff: automation — read/edit attributes with cursors, run a tool over many datasets in a loop, and wrap workflows in reusable functions.

Environment: run this notebook from ArcGIS Pro → Notebooks (the arcgispro-py3 Python), where the ArcGIS licence is active. It will not run in the gem530 open-source environment. See ../../environments/README.md.

The bundled data/MKRF.gdb holds the Malcolm Knapp Research Forest layers used here: roads, streams, trails, hydroline (all line features).

Learning outcomes¶

  1. Read attributes with a SearchCursor and edit with an UpdateCursor.
  2. Loop a tool over many datasets (batch processing).
  3. Wrap a workflow in a reusable function.
  4. Handle errors and log tool messages during automation.

1. Read attributes with a SearchCursor¶

A cursor iterates rows of a feature class. SearchCursor reads; you list the fields you want.

In [ ]:
import arcpy
arcpy.env.workspace = r"data/MKRF.gdb"
arcpy.env.overwriteOutput = True

with arcpy.da.SearchCursor("roads", ["OBJECTID", "SHAPE@LENGTH", "NAME"]) as cur:
    for oid, length, name in cur:
        print(oid, round(length, 1), name)

🌲 Why code this? A cursor is how a script reads the attribute table — every road length, every stand's species — without opening it in ArcGIS.

✅ Quick check — cursors¶

Which cursor reads rows, and which one changes them?

▶ Show answer SearchCursor reads; UpdateCursor reads and writes (call cur.updateRow(row)); InsertCursor adds new features.

2. Edit attributes with an UpdateCursor¶

UpdateCursor can change values row by row — e.g. fill a new length field.

In [ ]:
# add a field, then populate it (roads are lines, so we use length)
arcpy.management.AddField("roads", "length_km", "DOUBLE")
with arcpy.da.UpdateCursor("roads", ["SHAPE@LENGTH", "length_km"]) as cur:
    for row in cur:
        row[1] = row[0] / 1000.0      # metres -> kilometres
        cur.updateRow(row)
print("Filled length_km")

🌲 Forestry example. Filling a length_km or area_ha field for thousands of features is a cursor loop, not a manual field-calculator session.

3. Batch processing: one tool over many datasets¶

The automation win: loop a tool over every feature class instead of clicking each.

In [ ]:
for fc in arcpy.ListFeatureClasses():
    out = f"{fc}_buffer_100m"
    arcpy.analysis.Buffer(fc, out, "100 Meters")
    print("Buffered", fc, "->", out)

🌲 Why code this? Batch processing is the payoff of scripting: one loop buffers every layer in a geodatabase while you do something else.

✅ Quick check — batch safety¶

In a loop over many layers, why wrap each tool call in try/except?

▶ Show answer So one bad layer is logged and skipped instead of killing the whole batch part-way through.

4. Wrap a workflow in a reusable function¶

Package a repeatable task so you (and classmates) can reuse it — the Week 2 idea, applied to geoprocessing.

In [ ]:
def buffer_and_count(in_fc, distance="100 Meters"):
    """Buffer a feature class and return the output name + feature count."""
    out_fc = f"{in_fc}_buf"
    arcpy.analysis.Buffer(in_fc, out_fc, distance)
    n = int(arcpy.management.GetCount(out_fc)[0])
    return out_fc, n

name, count = buffer_and_count("roads", "75 Meters")
print(name, "has", count, "features")

🌲 Why code this? Wrapping a workflow in a function turns a one-off script into a tool your whole team can reuse on next year's delivery.

5. Robust automation: errors & logging¶

When looping over many datasets, catch errors so one bad layer doesn't stop the whole batch, and log messages.

In [ ]:
for fc in arcpy.ListFeatureClasses():
    try:
        arcpy.analysis.Buffer(fc, f"{fc}_buf", "100 Meters")
        print("OK:", fc)
    except arcpy.ExecuteError:
        print("FAILED:", fc, "->", arcpy.GetMessages(2))

Try it yourself. Change the batch buffer to write outputs into a separate "outputs" geodatabase, and add a print of each output's feature count.

🌲 Forestry example. Logging which layers succeeded and which failed is what makes an overnight batch trustworthy the next morning.

🎓 Additional learning (optional)¶

Bonus 1 — Adding new features with an InsertCursor¶

Why code this? Sometimes you must create data — a new sample-plot layer from GPS coordinates, or flag points from an analysis.

In [ ]:
import arcpy
arcpy.env.workspace = r"data/MKRF.gdb"
arcpy.env.overwriteOutput = True
# make an empty point layer, then insert two plots
arcpy.management.CreateFeatureclass(arcpy.env.workspace, "new_plots", "POINT",
                                    spatial_reference=arcpy.Describe("roads").spatialReference)
with arcpy.da.InsertCursor("new_plots", ["SHAPE@XY"]) as cur:
    cur.insertRow([(-122.57, 49.27)])
    cur.insertRow([(-122.55, 49.29)])
print("inserted:", arcpy.management.GetCount("new_plots")[0], "plots")

Bonus 2 — Progress logging for long batches¶

Why code this? A batch over hundreds of layers should tell you where it is and end with a summary you can trust.

In [ ]:
import arcpy
arcpy.env.workspace = r"data/MKRF.gdb"
fcs = arcpy.ListFeatureClasses()
ok, failed = [], []
for i, fc in enumerate(fcs, start=1):
    print(f"[{i}/{len(fcs)}] {fc} ...")
    try:
        arcpy.analysis.Buffer(fc, fc + "_b", "25 Meters")
        ok.append(fc)
    except arcpy.ExecuteError:
        failed.append(fc)
print("done. ok:", len(ok), "| failed:", failed)

🌲 This is what an operational overnight geoprocessing job looks like.

Working with AI (30-second habit)¶

Cursor code is a common source of bugs: field names must match the data exactly, and an open cursor can lock a dataset. If AI cursor code hangs or errors, check field names against ListFields, and make sure cursors are inside a with block so they close.
