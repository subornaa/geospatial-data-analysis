About this book

This open educational resource teaches Python programming for geospatial data analysis, starting from no assumed programming experience. You'll learn Python fundamentals with small geospatial examples, then work with tabular, vector, and raster data; automate GIS tasks; produce clear maps; and finish with an introduction to machine learning on satellite imagery.

Two environmental datasets recur throughout: the Malcolm Knapp Research Forest in British Columbia and the mangrove coast of northwest Madagascar, alongside Landsat imagery.

How to use this book

  • Each chapter is a hands-on lesson: read the explanation, run the code, and try the Quick check and Try it yourself prompts (answers are collapsible).
  • Most chapters run in an open-source Python environment (Pandas, GeoPandas, Shapely, Rasterio, NumPy, Matplotlib, scikit-learn). Two chapters use ArcPy, which requires ArcGIS Pro.
  • Each chapter ends with practice exercises to work through on your own.

4. File paths with pathlib¶

Your data lives in files. pathlib builds paths that work on Windows, Mac, and Linux. Use the / operator to join folders — cleaner and safer than typing "data\\sites.csv" by hand.

In [7]:
from pathlib import Path

data_dir = Path("data")            # a folder (relative path)
sites_file = data_dir / "sites.csv"  # join folder + filename

print("Full path:", sites_file)
print("File name:", sites_file.name)
print("Extension:", sites_file.suffix)

Full path: data\sites.csv
File name: sites.csv
Extension: .csv

We will treat relative paths (like data/sites.csv) as the reproducible default and revisit why in Week 5 (files & data quality).

🌲 Why code this? Environmental data lives in hundreds of files (shapefiles, rasters, CSVs). Building paths in code means the same analysis re-runs on a new folder of survey data, on any computer — no manual re-typing, no broken links.

5. Importing packages¶

Python's power comes from packages. You import a package, then use its tools with a dot: package.tool(). Here is the built-in math package.

In [8]:
import math

# straight-line distance between two of our plots (in DEGREES for now)

print("Planar distance:", round(d, 5), "degrees")

Notice the distance is in degrees, which is not a real-world length. Turning coordinates into metres needs a coordinate reference system — the topic of Week 5. For now, just notice the problem exists.

🌲 Why code this? Nobody re-writes geospatial math from scratch. Importing packages (NumPy, GeoPandas, Rasterio) lets you build on tested tools — the difference between an afternoon and a month on a mangrove-loss analysis.

6. Your first geometries: Shapely¶

A coordinate pair is just numbers. Shapely turns coordinates into geometry objects — Point, LineString, Polygon — the same objects that GeoPandas (Week 4) uses for whole datasets. This is a tiny first taste.

In [9]:
from shapely.geometry import Point, LineString, Polygon

# A Point: one location (lon, lat)
mkrf = Point(-122.57, 49.27)

# A LineString: an ordered path (e.g. a short trail) through several points
trail = LineString([(-122.573, 49.271), (-122.569, 49.268), (-122.566, 49.274)])

# A Polygon: a closed area (first and last point join automatically)
stand = Polygon([(-122.575, 49.270), (-122.565, 49.270),
                 (-122.565, 49.276), (-122.575, 49.276)])

print("Point:      ", mkrf)
print("Trail length:", round(trail.length, 5), "degrees")
print("Stand area: ", round(stand.area, 6), "square degrees")

Point:       POINT (-122.57 49.27)
Trail length: 0.01171 degrees
Stand area:  6e-05 square degrees

1. Comparison & logical operators¶

An operator like > returns a boolean (True/False). Logical operators combine booleans. Here we ask: is a point inside a bounding box?

In [ ]:
lat, lon = 49.27, -122.57          # a point in MKRF
# bounding box (min/max) roughly around MKRF
lat_min, lat_max = 49.20, 49.35
lon_min, lon_max = -122.70, -122.45

inside = (lat_min <= lat <= lat_max) and (lon_min <= lon <= lon_max)
print("Inside the box?", inside)

🌲 Why code this? A single comparison like dbh_cm > 50 becomes a rule you apply to a whole inventory — finding every large tree, or every stand steeper than 30°, without reading rows by hand.

2. Conditional statements (if / elif / else)¶

Do different things depending on a condition. Let's label a latitude by zone.

In [ ]:
def_lat = 49.27
if def_lat > 66.5:
    zone = "Arctic"
elif def_lat > 23.5:
    zone = "Temperate"
elif def_lat > 0:
    zone = "Tropical (N)"
else:
    zone = "Southern hemisphere"
print(def_lat, "->", zone)

Try it yourself. Change def_lat to -13.35 (the Madagascar site) and re-run. Which branch executes?

🌲 Forestry example. if/elif sorts data into categories — seedling / sapling / mature by DBH, or low / moderate / high fire risk by fuel load. The computer applies your rules the same way to thousands of records.

3. Loops¶

A for loop repeats once per item. A while loop repeats until a condition is false.

In [ ]:
plot_coords = [(-122.573, 49.271), (-122.569, 49.268), (-122.566, 49.274)]

# for loop: visit every coordinate
for i, (x, y) in enumerate(plot_coords):
    print(f"Plot {i}: lon={x}, lat={y}")

# while loop: a simple countdown
n = 3
while n > 0:
    print("countdown", n)
    n = n - 1

🌲 Why code this? Surveys produce many plots and many files. A loop runs the same step on every one — score 500 plots, read 200 rasters — from code you write once.

4. Functions: reusable code¶

A function packages steps under a name so you can reuse them. It takes parameters and can return a value. This is the most important idea this week.

In [ ]:
def is_valid_coord(lat, lon):
    """Return True if lat/lon are within valid Earth ranges."""
    return (-90 <= lat <= 90) and (-180 <= lon <= 180)

print(is_valid_coord(49.27, -122.57))   # True
print(is_valid_coord(120.0, -122.57))   # False: latitude out of range
In [ ]:
def bounding_box(coords):
    """Given a list of (lon, lat), return (min_lon, min_lat, max_lon, max_lat)."""
    lons = [c[0] for c in coords]
    lats = [c[1] for c in coords]
    return (min(lons), min(lats), max(lons), max(lats))

print("BBox:", bounding_box(plot_coords))

1. What CRS is my data in?¶

A geographic CRS (e.g. WGS84, EPSG:4326) uses degrees of lat/lon. A projected CRS (e.g. BC Albers EPSG:3005, or a UTM zone) uses metres — needed for real distances and areas.

In [ ]:
import geopandas as gpd

# In the course: gdf = gpd.read_file("data/fires_points.gpkg")  (your Week 4 output).
# Here we build a small MKRF (British Columbia) sample so BC Albers (EPSG:3005) is correct:
gdf = gpd.GeoDataFrame(
    {"site": ["MKRF-1", "MKRF-2", "MKRF-3"]},
    geometry=gpd.points_from_xy([-122.57, -122.55, -122.52], [49.27, 49.29, 49.31]),
    crs="EPSG:4326",
)
print("CRS:", gdf.crs)
print("Is it geographic (degrees)?", gdf.crs.is_geographic)

🌲 Why code this? Knowing whether your data is in degrees or metres decides whether an 'area' means anything. Nearly every geospatial mistake starts with an unchecked CRS.

✅ Quick check — which CRS for area?¶

To compute area in square metres, do you use a geographic CRS (EPSG:4326) or a projected one (EPSG:3005)?

▶ Show answer A projected CRS (e.g. EPSG:3005), whose units are metres. Geographic CRSs use degrees, which don't measure area.

2. Reproject and measure correctly¶

Degrees can't measure area. Reproject to a projected CRS, then measure. For polygons, compare the area before and after to see why this matters.

# BC Albers (metres) suits the MKRF area; Madagascar would use a UTM zone.

print("New CRS:", gdf_m.crs)
print("Now geographic?", gdf_m.crs.is_geographic)   # False -> metres

# stands = gpd.read_file("data/MKRF/stands.shp")

Bonus 2 — Repairing an invalid polygon¶

Why code this? Digitised stand boundaries often self-intersect ("bow-ties"), which breaks area and overlay tools. A one-line repair rescues them.

In [ ]:
import geopandas as gpd
from shapely.geometry import Polygon

gdf = gpd.GeoDataFrame(geometry=[bowtie], crs="EPSG:3005")
print("valid before?", bool(gdf.is_valid.iloc[0]))
gdf["geometry"] = gdf.buffer(0)                      # common repair
print("valid after? ", bool(gdf.is_valid.iloc[0]))

import pandas as pd, geopandas as gpd
from pathlib import Path

def plots_to_gpkg(df, out_path, to_crs="EPSG:3005"):
    """Table with lon/lat -> cleaned, reprojected GeoPackage. Returns the GeoDataFrame."""
    df = df.dropna(subset=["lon", "lat"])

    Path(out_path).parent.mkdir(exist_ok=True, parents=True)
    gdf.to_file(out_path, driver="GPKG")
    return gdf

demo = pd.DataFrame({"site": ["A", "B"], "lon": [-122.57, -122.55], "lat": [49.27, 49.29]})

1. Read attributes with a SearchCursor¶

A cursor iterates rows of a feature class. SearchCursor reads; you list the fields you want.

In [ ]:
import arcpy

arcpy.env.overwriteOutput = True

    for oid, length, name in cur:
        print(oid, round(length, 1), name)

🌲 Why code this? A cursor is how a script reads the attribute table — every road length, every stand's species — without opening it in ArcGIS.

✅ Quick check — cursors¶

Which cursor reads rows, and which one changes them?

▶ Show answer SearchCursor reads; UpdateCursor reads and writes (call cur.updateRow(row)); InsertCursor adds new features.

2. Edit attributes with an UpdateCursor¶

UpdateCursor can change values row by row — e.g. fill a new length field.

In [ ]:
# add a field, then populate it (roads are lines, so we use length)
arcpy.management.AddField("roads", "length_km", "DOUBLE")
with arcpy.da.UpdateCursor("roads", ["SHAPE@LENGTH", "length_km"]) as cur:
    for row in cur:
        row[1] = row[0] / 1000.0      # metres -> kilometres
        cur.updateRow(row)
print("Filled length_km")

🌲 Forestry example. Filling a length_km or area_ha field for thousands of features is a cursor loop, not a manual field-calculator session.

3. Batch processing: one tool over many datasets¶

The automation win: loop a tool over every feature class instead of clicking each.

In [ ]:
for fc in arcpy.ListFeatureClasses():
    out = f"{fc}_buffer_100m"
    arcpy.analysis.Buffer(fc, out, "100 Meters")

🌲 Why code this? Batch processing is the payoff of scripting: one loop buffers every layer in a geodatabase while you do something else.

✅ Quick check — batch safety¶

In a loop over many layers, why wrap each tool call in try/except?

▶ Show answer So one bad layer is logged and skipped instead of killing the whole batch part-way through.

4. Wrap a workflow in a reusable function¶

Package a repeatable task so you (and classmates) can reuse it — the Week 2 idea, applied to geoprocessing.

In [ ]:
def buffer_and_count(in_fc, distance="100 Meters"):
    """Buffer a feature class and return the output name + feature count."""
    out_fc = f"{in_fc}_buf"
    arcpy.analysis.Buffer(in_fc, out_fc, distance)
    n = int(arcpy.management.GetCount(out_fc)[0])
    return out_fc, n

name, count = buffer_and_count("roads", "75 Meters")
print(name, "has", count, "features")

🌲 Why code this? Wrapping a workflow in a function turns a one-off script into a tool your whole team can reuse on next year's delivery.

Chapter 9 — Raster Data with NumPy & Rasterio

Vector data was points and polygons. Raster data is a grid of cells — elevation, satellite bands, land cover. The key idea: a raster band is a NumPy array. Rasterio reads/writes the georeferenced files; NumPy does the math; Matplotlib displays it.

Run in Python (gem530). The NumPy cells run anywhere; the Rasterio cells need a raster file (provided) and the gem530 environment.

Learning outcomes¶

  1. Describe raster structure: bands, rows, columns, cells, NoData.
  2. Read a raster band into a NumPy array and inspect metadata.
  3. Do array math, masking, and simple reclassification.
  4. Compute a simple index (e.g. a difference or NDVI).
  5. Write a GeoTIFF and display it with Matplotlib.

1. A raster is an array¶

Let's build a tiny synthetic elevation raster (4×4) so the NumPy ideas are concrete. 255 marks NoData (cells with no valid value).

In [ ]:
import numpy as np

band = np.array([
    [10, 12, 15, 255],
    [11, 13, 14, 255],
    [ 9, 10, 255, 255],
    [ 8,  9, 10, 11],
], dtype=float)

print("shape (rows, cols):", band.shape)
print("min/max (incl. NoData):", band.min(), band.max())

🌲 Why code this? Elevation, canopy height, burn severity, satellite bands — all arrive as grids. Seeing a raster as an array is what lets you compute on millions of forest pixels at once.

2. Handle NoData with a mask¶

Replace the NoData value with np.nan so it doesn't corrupt statistics.

In [ ]:
nodata = 255
masked = np.where(band == nodata, np.nan, band)
print("mean elevation (NoData ignored):", round(np.nanmean(masked), 2))

🌲 Forestry example. Cloud, shadow and off-image pixels are NoData. Masking them is why your mean canopy height describes the forest, not the holes in the data.

✅ Quick check — NoData¶

Why replace a NoData value (255) with np.nan before averaging?

▶ Show answer NoData isn't a measurement — leaving 255 in would drag the mean upward. Mask it, then use np.nanmean() so only real pixels count.

3. Array math & reclassification¶

Operations apply to every cell at once. Here we reclassify into low/high zones.

In [ ]:
# add 100 m to every valid cell (array math)
raised = masked + 100
print(raised)

# reclassify: 1 = low (<12), 2 = high (>=12); NoData stays NaN
reclass = np.where(np.isnan(masked), np.nan, np.where(masked < 12, 1, 2))
print("\nReclassified:\n", reclass)

🌲 Why code this? Reclassifying continuous values into classes — low/moderate/high burn severity, slope classes — is how raw measurements become management categories.

4. A simple index (NDVI)¶

Vegetation indices combine bands. NDVI = (NIR − Red) / (NIR + Red). With two small synthetic bands:

In [ ]:
red = np.array([[0.20, 0.22], [0.19, 0.25]])
nir = np.array([[0.40, 0.55], [0.38, 0.60]])
ndvi = (nir - red) / (nir + red)
print("NDVI:\n", np.round(ndvi, 3))

🌲 Forestry example. NDVI turns raw bands into a vegetation-vigour map: the workhorse index for monitoring forest health, drought stress and regrowth after harvest or fire.

Chapter 11 — Introductory Machine Learning

Mapping burned area from Landsat imagery¶

We introduce machine-learning programming with scikit-learn on a real remote- sensing task: teach a model to label each pixel as burned or unburned from Landsat 8 spectral bands. We train on one date and then test the model on the same area weeks later — a powerful lesson in generalisation.

This is an introduction to ML programming, not spatial statistics (that's your R course). Run in Python (gem530).

Data (data/):

  • LC08_L1TP_20190702_image1.tif — Landsat 8 scene (the features, one per band)
  • fires_clip_bi.tif — binary burned/unburned labels for that scene
  • LC08_L1TP_20190819_image2.tif — same area, ~6 weeks later (unseen test)

Learning outcomes¶

  1. Turn a multi-band raster into an ML table of (pixels, bands).
  2. Split into training and test sets and fit a classifier.
  3. Evaluate with accuracy, a confusion matrix, and kappa.
  4. Predict across a whole image and map the result.
  5. Test the model on a new date and reason about overfitting/generalisation.
  6. State the limitations of the model.

1. Read the imagery and labels (Rasterio)¶

Each Landsat band becomes a feature; the fires raster gives the label for every pixel.

In [ ]:

    landsat = src.read()          # shape: (bands, rows, cols)
    meta = src.meta

🌲 Why code this? Supervised learning needs examples: imagery (the evidence) plus labels (the truth). Assembling that pair correctly is most of the work in applied remote sensing.

2. Reshape into an ML table¶

scikit-learn expects X as (samples, features) — for imagery that means (pixels, bands). We flatten the rows×cols grid and move bands to the last axis.

In [ ]:
bands, rows, cols = landsat.shape
X = landsat.reshape(bands, rows * cols)     # (bands, pixels)
X = np.swapaxes(X, 0, 1)                     # (pixels, bands)  <- what sklearn wants
y = fires.reshape(rows * cols)               # (pixels,) labels
print("X:", X.shape, "| y:", y.shape, "| burned pixels:", int(y.sum()))

🌲 Why code this? Models want a table — one row per pixel, one column per band. Reshaping the image into that table is the bridge between a raster and machine learning.

3. Train / test split & fit a model¶

We hold out part of the pixels to test on. A Decision Tree is a simple, fast first classifier. random_state makes it reproducible.

In [ ]:
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.30, random_state=42)
clf = DecisionTreeClassifier(max_depth=8, random_state=42)   # max_depth limits overfitting
clf.fit(X_train, y_train)
print("model trained on", X_train.shape[0], "pixels")

🌲 Forestry example. Training on part of a burn and testing on the rest tells you whether the model learned burn signatures or just memorised those pixels.

✅ Quick check — why split?¶

Why fit on a training set and score on a test set?

▶ Show answer So the score reflects performance on unseen data. Scoring on data the model trained on is optimistic (that's data leakage).

4. Evaluate on the held-out test pixels¶

In [ ]:
from sklearn.metrics import accuracy_score, confusion_matrix, cohen_kappa_score
pred = clf.predict(X_test)
print("accuracy:", round(accuracy_score(y_test, pred), 3))
print("kappa:", round(cohen_kappa_score(y_test, pred), 3))
print("confusion matrix [rows=actual, cols=pred]:\n", confusion_matrix(y_test, pred))

🌲 Why code this? Accuracy alone hides trouble when classes are unbalanced. A confusion matrix shows which class is actually being missed — the burned area, usually.

5. Predict the whole image and map it¶

Predictions matter most when we can see them in space — predict every pixel and reshape back to the image grid (this is 'joining predictions back to geospatial data').

In [ ]:
pred_image = clf.predict(X).reshape(rows, cols)

fig, ax = plt.subplots(1, 2, figsize=(9, 4))
ax[0].imshow(fires, cmap="Reds");      ax[0].set_title("Actual burned area")
ax[1].imshow(pred_image, cmap="Reds"); ax[1].set_title("Predicted burned area")
plt.show()

🌲 Forestry example. Predicting the whole scene turns a trained model into a map — the deliverable a fire or forest-health program actually uses.

6. The real test: a different date (generalisation)¶

Our model has only seen one day. Let's apply it to the same area ~6 weeks later. If accuracy drops a lot, the model overfit to that single scene.

In [ ]:
with rasterio.open("data/LC08_L1TP_20190819_image2.tif") as src:
    later = src.read()
Xlater = np.swapaxes(later.reshape(bands, rows * cols), 0, 1)

acc_later = clf.score(Xlater, y)   # compare to the same fire labels
print("accuracy on the later date:", round(acc_later, 3))
print("(compare with the test accuracy above — a big drop signals overfitting)")

🌲 Why code this? A model that works on one date may fail on another (different sun angle, phenology, sensor). Testing on a new date is the honest test of transferability.

✅ Quick check — generalisation¶

Accuracy is 0.89 on the test split but 0.82 on a later date. What does that tell you?

▶ Show answer The model transfers imperfectly across time — conditions changed (phenology, sun angle, atmosphere). Report the later-date number too; it's the realistic one.

7. Limitations (always state them)¶

Be honest about what this model can and cannot do:

  • Trained on one scene, one date, one area — it may not transfer to other regions/ seasons/sensors.
  • Pixels are treated independently (no spatial context).
  • Labels themselves have error; class imbalance (few burned pixels) inflates accuracy.
  • Predicting over pixels the model trained on overstates performance — trust the held-out and later-date results.

🌲 Why code this? Stating limits — sample bias, no spatial validation, one sensor, one season — is what separates a defensible result from an over-claimed one.

Bonus 2 — Accuracy can lie: class balance¶

Why code this? If 95% of pixels are unburned, a model that predicts "unburned" everywhere scores 95% and is useless. Always check the balance.

In [ ]:
import numpy as np
from sklearn.metrics import accuracy_score, confusion_matrix
truth = np.array(["unburned"]*95 + ["burned"]*5)
lazy  = np.array(["unburned"]*100)          # predicts one class for everything
print("accuracy of the lazy model:", accuracy_score(truth, lazy))
print(confusion_matrix(truth, lazy, labels=["burned","unburned"]))
print("-> it never finds a single burned pixel!")

🌲 This is why we report the confusion matrix (and kappa) alongside accuracy.
