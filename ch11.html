Chapter 11 — Introductory Machine Learning

Mapping burned area from Landsat imagery¶

We introduce machine-learning programming with scikit-learn on a real remote- sensing task: teach a model to label each pixel as burned or unburned from Landsat 8 spectral bands. We train on one date and then test the model on the same area weeks later — a powerful lesson in generalisation.

This is an introduction to ML programming, not spatial statistics (that's your R course). Run in Python (gem530).

Data (data/):

  • LC08_L1TP_20190702_image1.tif — Landsat 8 scene (the features, one per band)
  • fires_clip_bi.tif — binary burned/unburned labels for that scene
  • LC08_L1TP_20190819_image2.tif — same area, ~6 weeks later (unseen test)

Learning outcomes¶

  1. Turn a multi-band raster into an ML table of (pixels, bands).
  2. Split into training and test sets and fit a classifier.
  3. Evaluate with accuracy, a confusion matrix, and kappa.
  4. Predict across a whole image and map the result.
  5. Test the model on a new date and reason about overfitting/generalisation.
  6. State the limitations of the model.

1. Read the imagery and labels (Rasterio)¶

Each Landsat band becomes a feature; the fires raster gives the label for every pixel.

In [ ]:
import numpy as np, rasterio
import matplotlib.pyplot as plt

with rasterio.open("data/LC08_L1TP_20190702_image1.tif") as src:
    landsat = src.read()          # shape: (bands, rows, cols)
    meta = src.meta
with rasterio.open("data/fires_clip_bi.tif") as src:
    fires = src.read(1)           # shape: (rows, cols); 1 = burned, 0 = not

print("landsat:", landsat.shape, "| fires:", fires.shape)
In [ ]:
# quick look: the near-infrared band and the fire labels
fig, ax = plt.subplots(1, 2, figsize=(9, 4))
ax[0].imshow(landsat[4], cmap="Greys"); ax[0].set_title("Landsat NIR band")
ax[1].imshow(fires, cmap="Reds");       ax[1].set_title("Burned (1) / not (0)")
plt.show()

🌲 Why code this? Supervised learning needs examples: imagery (the evidence) plus labels (the truth). Assembling that pair correctly is most of the work in applied remote sensing.

2. Reshape into an ML table¶

scikit-learn expects X as (samples, features) — for imagery that means (pixels, bands). We flatten the rows×cols grid and move bands to the last axis.

In [ ]:
bands, rows, cols = landsat.shape
X = landsat.reshape(bands, rows * cols)     # (bands, pixels)
X = np.swapaxes(X, 0, 1)                     # (pixels, bands)  <- what sklearn wants
y = fires.reshape(rows * cols)               # (pixels,) labels
print("X:", X.shape, "| y:", y.shape, "| burned pixels:", int(y.sum()))

🌲 Why code this? Models want a table — one row per pixel, one column per band. Reshaping the image into that table is the bridge between a raster and machine learning.

3. Train / test split & fit a model¶

We hold out part of the pixels to test on. A Decision Tree is a simple, fast first classifier. random_state makes it reproducible.

In [ ]:
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.30, random_state=42)
clf = DecisionTreeClassifier(max_depth=8, random_state=42)   # max_depth limits overfitting
clf.fit(X_train, y_train)
print("model trained on", X_train.shape[0], "pixels")

🌲 Forestry example. Training on part of a burn and testing on the rest tells you whether the model learned burn signatures or just memorised those pixels.

✅ Quick check — why split?¶

Why fit on a training set and score on a test set?

▶ Show answer So the score reflects performance on unseen data. Scoring on data the model trained on is optimistic (that's data leakage).

4. Evaluate on the held-out test pixels¶

In [ ]:
from sklearn.metrics import accuracy_score, confusion_matrix, cohen_kappa_score
pred = clf.predict(X_test)
print("accuracy:", round(accuracy_score(y_test, pred), 3))
print("kappa:", round(cohen_kappa_score(y_test, pred), 3))
print("confusion matrix [rows=actual, cols=pred]:\n", confusion_matrix(y_test, pred))

🌲 Why code this? Accuracy alone hides trouble when classes are unbalanced. A confusion matrix shows which class is actually being missed — the burned area, usually.

5. Predict the whole image and map it¶

Predictions matter most when we can see them in space — predict every pixel and reshape back to the image grid (this is 'joining predictions back to geospatial data').

In [ ]:
pred_image = clf.predict(X).reshape(rows, cols)

fig, ax = plt.subplots(1, 2, figsize=(9, 4))
ax[0].imshow(fires, cmap="Reds");      ax[0].set_title("Actual burned area")
ax[1].imshow(pred_image, cmap="Reds"); ax[1].set_title("Predicted burned area")
plt.show()

🌲 Forestry example. Predicting the whole scene turns a trained model into a map — the deliverable a fire or forest-health program actually uses.

6. The real test: a different date (generalisation)¶

Our model has only seen one day. Let's apply it to the same area ~6 weeks later. If accuracy drops a lot, the model overfit to that single scene.

In [ ]:
with rasterio.open("data/LC08_L1TP_20190819_image2.tif") as src:
    later = src.read()
Xlater = np.swapaxes(later.reshape(bands, rows * cols), 0, 1)

acc_later = clf.score(Xlater, y)   # compare to the same fire labels
print("accuracy on the later date:", round(acc_later, 3))
print("(compare with the test accuracy above — a big drop signals overfitting)")

🌲 Why code this? A model that works on one date may fail on another (different sun angle, phenology, sensor). Testing on a new date is the honest test of transferability.

✅ Quick check — generalisation¶

Accuracy is 0.89 on the test split but 0.82 on a later date. What does that tell you?

▶ Show answer The model transfers imperfectly across time — conditions changed (phenology, sun angle, atmosphere). Report the later-date number too; it's the realistic one.

7. Limitations (always state them)¶

Be honest about what this model can and cannot do:

  • Trained on one scene, one date, one area — it may not transfer to other regions/ seasons/sensors.
  • Pixels are treated independently (no spatial context).
  • Labels themselves have error; class imbalance (few burned pixels) inflates accuracy.
  • Predicting over pixels the model trained on overstates performance — trust the held-out and later-date results.

🌲 Why code this? Stating limits — sample bias, no spatial validation, one sensor, one season — is what separates a defensible result from an over-claimed one.

Common errors this week (and the fix)¶

Symptom Cause Fix
suspiciously perfect accuracy scored on training data (leakage) split before fitting; report the test score
accuracy high but map looks wrong unbalanced classes check the confusion matrix, not just accuracy
results change every run no random_state set random_state=0 for reproducibility
shape error in fit X and y lengths differ check X.shape and len(y)

🎓 Additional learning (optional)¶

Bonus 1 — Which band mattered? (feature importance)¶

Why code this? Knowing why a model decided something builds trust — and often confirms the ecology (e.g. NIR drops sharply after fire).

In [ ]:
import numpy as np, pandas as pd
from sklearn.ensemble import RandomForestClassifier
rng = np.random.default_rng(7)
X = pd.DataFrame({"red": np.r_[rng.normal(0.06,0.02,80), rng.normal(0.18,0.03,60)],
                  "nir": np.r_[rng.normal(0.45,0.04,80), rng.normal(0.18,0.04,60)]})
y = ["forest"]*80 + ["burned"]*60
m = RandomForestClassifier(n_estimators=50, random_state=0).fit(X, y)
for band, imp in zip(X.columns, m.feature_importances_):
    print(f"{band}: {imp:.2f}")

🌲 A high NIR importance matches the ecology: healthy canopy reflects NIR strongly, burned ground doesn't.

Bonus 2 — Accuracy can lie: class balance¶

Why code this? If 95% of pixels are unburned, a model that predicts "unburned" everywhere scores 95% and is useless. Always check the balance.

In [ ]:
import numpy as np
from sklearn.metrics import accuracy_score, confusion_matrix
truth = np.array(["unburned"]*95 + ["burned"]*5)
lazy  = np.array(["unburned"]*100)          # predicts one class for everything
print("accuracy of the lazy model:", accuracy_score(truth, lazy))
print(confusion_matrix(truth, lazy, labels=["burned","unburned"]))
print("-> it never finds a single burned pixel!")

🌲 This is why we report the confusion matrix (and kappa) alongside accuracy.

Working with AI (30-second habit)¶

The classic ML mistake is data leakage / testing on training data. Notice we report the held-out test and the later-date accuracy, not the score on pixels the model trained on. If AI code reports one suspiciously perfect number, check what data it was evaluated on.
