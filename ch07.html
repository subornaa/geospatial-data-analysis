Chapter 7 — ArcPy: Tools & Environments

For two weeks we use ArcPy — ArcGIS Pro's Python package — to automate geoprocessing with scripts (no clicking through the GUI). Everything you did with GeoPandas/Rasterio has a place here too; ArcPy's distinct value is scripting an existing GIS platform and batch-automating repetitive tasks.

Environment: run this notebook from ArcGIS Pro → Notebooks (the arcgispro-py3 Python), where the ArcGIS licence is active. It will not run in the gem530 open-source environment. See ../../environments/README.md.

The bundled data/MKRF.gdb holds the Malcolm Knapp Research Forest layers used here: roads, streams, trails, hydroline (all line features).

Learning outcomes¶

  1. Import ArcPy and set the workspace and environment.
  2. Call a geoprocessing tool from Python with parameters.
  3. List datasets and fields in a workspace.
  4. Use Describe to inspect a dataset.
  5. Read tool messages and handle errors; name outputs systematically.

1. ArcPy is a package¶

You import arcpy like any package. The workspace is the default folder/ geodatabase for inputs and outputs; overwriteOutput lets you re-run cells.

In [ ]:
import arcpy

arcpy.env.workspace = r"data/MKRF.gdb"        # bundled MKRF geodatabase to the provided geodatabase
arcpy.env.overwriteOutput = True
print("Workspace:", arcpy.env.workspace)

🌲 Why code this? Treating ArcPy as just another package is the mental shift: the same Python you've written for five weeks now drives a professional GIS.

2. Call a geoprocessing tool¶

Tools live in toolboxes (analysis, management, ...). Here we buffer roads by 100 m — the same idea as a GeoPandas buffer, but running ArcGIS's tool.

In [ ]:
# arcpy.analysis.Buffer(in_features, out_feature_class, buffer_distance)
arcpy.analysis.Buffer("roads", "roads_buffer_100m", "100 Meters")
print("Created roads_buffer_100m")
print(arcpy.GetMessages())     # read what the tool reported

🌲 Forestry example. Buffering roads or streams, clipping stands to a watershed — the tools you'd click in ArcGIS become one repeatable line you can re-run on new data.

✅ Quick check — calling a tool¶

What's the modern way to call the Buffer tool?

▶ Show answer arcpy.analysis.Buffer(in_fc, out_fc, "100 Meters") — tools live in toolbox modules (analysis, management, …).

3. Inputs, outputs & systematic naming¶

Give outputs predictable names so batch results stay organized. Build names from the input + operation.

In [ ]:
in_fc = "streams"
distance = "50 Meters"
out_fc = f"{in_fc}_buffer_{distance.split()[0]}m"   # -> streams_buffer_50m
arcpy.analysis.Buffer(in_fc, out_fc, distance)
print("Created", out_fc)

🌲 Why code this? Systematic output names (roads_buf_100m) mean a batch of 50 outputs stays understandable six months later — a real problem in operational forestry.

4. List datasets and fields¶

Discover what's in a workspace — essential before automating over many layers.

In [ ]:
feature_classes = arcpy.ListFeatureClasses()
print("Feature classes:", feature_classes)

for f in arcpy.ListFields("roads"):
    print(f.name, "|", f.type)

🌲 Why code this? Listing datasets and fields is how a script discovers what's in a geodatabase, so it can process whatever this year's delivery contains.

5. Describe a dataset¶

Describe returns properties (shape type, spatial reference, extent) — useful for decisions in a script.

In [ ]:
desc = arcpy.Describe("roads")
print("Type:", desc.dataType)
print("Shape:", desc.shapeType)
print("CRS:", desc.spatialReference.name)

🌲 Forestry example. Describe tells your script the geometry type and CRS before it acts — so the same tool works on a stand polygon layer and a road line layer.

✅ Quick check — Describe¶

Name two things arcpy.Describe("roads") can tell you.

▶ Show answer Its shapeType (Polyline/Polygon/Point) and its spatialReference (CRS) — plus data type and extent. Scripts branch on these.

6. Tool messages & error handling¶

Tools report messages; wrap risky calls in try / except arcpy.ExecuteError and print the messages to debug.

In [ ]:
try:
    arcpy.analysis.Clip("streams", "study_area", "streams_clipped")
    print(arcpy.GetMessages())
except arcpy.ExecuteError:
    print("Tool error:\n", arcpy.GetMessages(2))   # 2 = error messages

🌲 Why code this? Tool messages and try/except are how an overnight batch over 200 layers reports what worked instead of dying silently.

Common errors this week (and the fix)¶

Symptom Cause Fix
"output already exists" re-running a cell arcpy.env.overwriteOutput = True, or a unique name
tool "not found" wrong toolbox path arcpy.analysis.Buffer, not arcpy.Buffer
RuntimeError: dataset not found workspace/name wrong check arcpy.env.workspace and ListFeatureClasses()
licence error not running in ArcGIS Pro's Python open ArcGIS Pro → Notebooks

🎓 Additional learning (optional)¶

Bonus 1 — Environment settings that save hours¶

Why code this? arcpy.env applies a setting to every later tool — clip everything to one study area, or snap all outputs to a common grid, without repeating parameters.

In [ ]:
import arcpy
arcpy.env.workspace = r"data/MKRF.gdb"
arcpy.env.overwriteOutput = True
# arcpy.env.extent = "roads"        # process only this area
# arcpy.env.outputCoordinateSystem = arcpy.SpatialReference(3005)   # force BC Albers
print("workspace:", arcpy.env.workspace)
print("overwrite :", arcpy.env.overwriteOutput)

Bonus 2 — Check before you write¶

Why code this? In a long batch you want to skip work that's already done, and never crash on a missing input.

In [ ]:
import arcpy
arcpy.env.workspace = r"data/MKRF.gdb"
for fc in ["roads", "streams", "does_not_exist"]:
    if arcpy.Exists(fc):
        print(fc, "-> found,", arcpy.management.GetCount(fc)[0], "features")
    else:
        print(fc, "-> MISSING, skipping")

🌲 arcpy.Exists is the guard that keeps an overnight batch alive.

Working with AI (30-second habit)¶

AI often mixes up ArcPy versions/tool paths (e.g. arcpy.Buffer_analysis vs arcpy.analysis.Buffer). Confirm the tool name in the current Esri documentation, and read arcpy.GetMessages() rather than trusting that a tool "probably worked".
